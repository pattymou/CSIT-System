# CSIT x KM A-D Mock E2E

The `CSIT KM A-D Mock E2E` workflow is the repeatable acceptance gate for Tasks A-D. It uses the existing ApprovalFramework tests and in-process Mock KM ingestion/deletion servers. It never calls an LLM API or Anderson KM.

Each run creates a migrated PostgreSQL 16 template and seven isolated databases per round. The template starts from the schema generated by the repository's immutable initial commit `a2d6224`, records its seven baseline migrations, and applies the current migration chain. Three rounds run against fresh clones. Missing connection variables are fatal in CI mode, so an unexecuted PostgreSQL test cannot be counted as passed.

The workflow keeps all runtime KM integration and deletion switches false. Tests enable only their explicitly constructed mock clients. It does not use DEV/Production databases, Shared Identity, formal NAS, or the DEV Ready tag/deployment workflow.

## Run manually

In GitHub, open **Actions**, select **CSIT KM A-D Mock E2E**, choose **Run workflow**, select `feature/km-stage-integration`, and run it.

The `csit-km-a-d-mock-e2e-<run-id>` artifact contains each round's TRX, Cobertura coverage, diagnostic log and status, plus the combined Markdown/JSON summary, coverage matrix CSV and individual test result CSV.
