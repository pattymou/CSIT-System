# CSIT 操作手冊 V2 盤點與驗收

本次目錄以 `SidebarCatalog` 將內部 `IMenuManagementService` 的已啟用項目與角色可見性轉成側欄及手冊共同資料；RD 服務選單與手冊共同使用 `RdServices`。內容以 Route 對應，顯示名稱與排序來自目前選單。操作手冊入口、外部連結及側欄隱藏的選單管理頁不建立功能章節。

## 舊版章節處置

| 舊章節 | 處置與新版位置 |
| --- | --- |
| 系統登入與進入 CSIT | 改為登入與登出前言 |
| 預約申請 / Reservation | 重寫為「設備預約管理」 |
| Project / Case / Task | 刪除獨立章節；已接受申請的測試工作整合到「驗證申請專區」 |
| 測試報告 / Supervisor Review | 刪除舊 Task 入口；檔案審核整合到「主管待審」及「我的提交項目」 |
| 資產管理 / Equipment & Goods | 刪除停用 Goods 流程；重寫為「設備管理」 |
| 設定與基礎資料 / System Options & Master Data | 重寫為「參數管理」 |
| 測試環境 / Test Environment | 整合到「設備管理」的測試環境步驟 |
| 角色、權限與帳號管理 | 帳號操作整合到「帳號管理」；權限說明放到各功能 |
| 驗證申請單與案件結案 | 分別整合到「驗證測試申請單」與「驗證申請專區」 |
| 主管審核中心 | 重寫為選單名稱「主管待審」 |
| KM 分析與設備綜合分析 | 分拆到「KM 分析檢視」「KM 處理佇列」與「設備管理」 |
| 文件專區 | 依現行三層文件頁重寫 |
| 廠商資訊管理 | 依現行廠商頁重寫 |
| 系統設定與維護 | 分拆到驗證申請單設定、參數管理、文件資料夾管理、KM 管理及帳號管理 |
| 附件送審、正式入庫與刪除 | 不再獨立成章；規則放入實際來源功能 |

RD 舊 7 章改為「登入與登出」前言及依側欄排序的 3 個功能章節。新增申請、草稿、附件、送審、退回、拒絕、接受等子步驟均置於「系統驗證申請單」。

## 現行功能覆蓋

Admin 的內部目錄：主管待審；Department：驗證測試申請單、驗證申請專區、設備管理、設備預約管理、文件專區、廠商資訊管理；Administration：驗證申請單設定、參數管理、文件資料夾管理、KM 分析檢視、KM 處理佇列、帳號管理。一般員工的第一群組為「我的項目／我的提交項目」，管理群組依 Policy、AdminOnly 與 KM 佇列讀取權限動態縮減。RD 的「RD 服務」依序為首頁、系統驗證申請單、設備預約。

DEV 選單中已停用的「專案管理」「認證管理」「貨品管理」不在目錄。選單管理頁被現行側欄特別隱藏，操作手冊入口不循環建立章節。

## 截圖與驗收方式

原有 32 張 PNG；移除過時的內部 `validation-application-form.png`，以合法 RD Session 的現行動態申請表取代 `rd/application-new.png`。其餘 30 張沿用，總數 31 張；內部 25、RD 5、共用 1。所有引用均維持在 `/api/manual/assets/{internal|rd|shared}/` 受保護端點，未放入公開 `wwwroot`。

`ManualContentCoverageTests` 驗證功能映射、選單順序、停用舊功能、角色可見性、RD 圖片隔離、圖片檔案與 PNG 格式，以及手冊頁授權 Policy。`ManualAssetAccessTests` 驗證內部／RD／未登入的直接圖片請求。DEV Ready 後還須以合法內部及 RD Session 檢視實際目錄、每一章與圖片；比對 DEV 選單 API、預約政策設定、動態表單及工作狀態；檢查 `current.json`、部署日誌、Smoke 與 Production 5010 PID。
