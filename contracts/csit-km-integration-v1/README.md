# CSIT ↔ KM integration v1 wire contract

The four JSON Schema Draft 2020-12 files in this directory are the contract authority. Both CSIT and KM can validate their serialized JSON against these same files. Enable `format` assertion in the validator to check UUID and RFC 3339 date-time values; the CSIT tests set `RequireFormatValidation = true`. The CSIT contract gate runs `dotnet test tests/ApprovalFramework.Tests/ApprovalFramework.Tests.csproj --filter FullyQualifiedName~CanonicalKmContractTests`.

`ingestion-request.schema.json` describes the body sent by `KmIntegrationClient` after `KmSyncWorker.BuildRequestAsync` resolves an approved, committed Test Report. The request uses `project.number`, `case.number`, and `task.number`; `code` is not a wire alias. `eventId`, `documentId`, and each reference `id` are C# `Guid` values serialized as UUID strings. The DTO declares `case` and `task` nullable, but this v1 worker returns no request unless both records exist and belong to the project; a transmitted `TestReportCommitted` request therefore has objects at all three levels. `KmReference.Number` and `Name` remain nullable in the DTO and the worker does not reject null values, so those properties are required on the wire but may contain JSON null.

Each callback schema requires its status-specific timestamp inside `timestamps`. Other timestamp members may be omitted or null. `Failed` also requires a nonblank `error.code` and `error.message`. The callback DTO permits nullable `timestamps` and `error`, while `KmIntegrationController.Status` rejects the missing values required for each status. These schemas express the accepted v1 callbacks, without substituting `updatedAt` or any alternate timestamp spelling.

The schemas do not authorize a callback or dispatch a worker. The sender still needs the existing service token and correlation checks. Contract tests exercise the actual CSIT HTTP serializer and callback controller with in-memory persistence; they do not contact live KM or a production database.
